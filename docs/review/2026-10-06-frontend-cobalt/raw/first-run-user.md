## First-Run User Review

I walked the new-user path in order against the capture set in `docs/review/2026-10-06-frontend-cobalt/shots/` — landing (01), login modal (02), register modal (03), dashboard light/dark (04/05), then workspace (06/12), project (07/13), ideas wall (08/14), PRD desk (09/15), roadmap (10/16), versions (11/17), profile (18), plus the narrow shots (19/20) — and read the code behind each beat: `landing_page.dart`, `auth_door.dart`, `auth_form.dart`, `dashboard_page.dart`, `app.dart`, `product_dock.dart`, `workspace_page.dart`, `project_page.dart`, `ideas_page.dart`, `prd_desk.dart`, `coach_panel.dart`, `versions_stack.dart`, and the zh/en catalogs. I scored the first three minutes **4/10**.

**What works.** The landing page is the best part of the funnel. The hero ("把想法，一件件打磨出来。") plus one sentence of subtitle tells a new visitor exactly what InsideOut does — capture ideas, let an AI coach grind them into a PRD, split them into a parallel roadmap, and track real commits to delivery — and the four-step assembly story below reinforces it (`landing_page.dart:14-19`). The register modal states the password rule inline. The ideas wall is the strongest in-product surface: the capture input is the visual focus, and the privacy caption ("仅自己可见——想法默认只有作者能看到…") is precisely the reassurance a first-time user needs before typing an unpolished thought. Light and dark themes are coherent across every paired shot, zh/en catalogs are at parity, and the versions page's per-audience readiness checklist is a genuinely good piece of product design. The roadmap empty state tells you what to do next.

**Where it breaks.** The first failure is the chrome. The floating dock renders at the *vertical center* of every signed-in screen, not the bottom: the dashboard chapter paragraph is clipped mid-sentence (04/05), the workspace delete row is half-hidden (06/12), and the versions checklist's last two items are unreadable (11/17). The cause is in `product_dock.dart:26-29`: the widget returns `SafeArea(child: Center(...))` and `AppScaffold` (app.dart:135) inserts it as `Scaffold.bottomNavigationBar` — a `Center` expands to fill the loose height the Scaffold offers, so the nav bar silently becomes full-height and the pill centers in it. The intended `static const height = 88.0` exists but is never referenced. This one bug also explains why the workspace page's create-project FAB (its only creation affordance, `workspace_page.dart:115-118`) is nowhere in shots 06/12: the FAB anchors relative to a nav bar whose top is at the viewport top. A new user in a fresh workspace quite literally cannot start a project.

The dock also teaches unreliability. `DockItem.evidence` unconditionally calls `stay()` (product_dock.dart:129-130) — a labeled navigation button that is a guaranteed no-op with no toast, no disabled state. `DockItem.version` navigates to `/prd/$prd`, which is the page already open when you're on the desk — another silent dead click (captures.md A6). On top of that, the "unfinished" nudge replaces the 提交 label with the longer "未完成：提交", which overflows its slot and lands as a white pill on the icon (10/18) — designed behavior that reads as a stuck tooltip.

Information architecture adds friction. The project page headlines itself "证据" in the largest type, with the actual project name demoted beneath (`project_page.dart:150-155`), so a user who clicked "Onboarding Revamp" can't confirm where they are. The workspace page is four label-only rows — 想法 / 设置 / 编辑 / 删除这个工作区 — with no chevron and no description, and the destructive row is styled identically to the neutral ones (A7); FieldCard has no trailing affordance at all. The dashboard hides "create workspace" once you have one (the button only exists in the empty state, `dashboard_page.dart:231-247`). The auth modal card itself is untitled: the disc, "InsideOut", and the "登录/创建账号" greeting are siblings *above* the card in a centered Column (`auth_door.dart:50-71`), which is why the wordmark floats over the landing hero and collides with the 开始打磨/登录 buttons in shot 02 (the lead reviewer's confirmed defect) — and even when it doesn't collide, the greeting is 12px bodySmall dark text on a black54 scrim.

Data surfaces feel half-finished. The updates feed shows a raw English enum chip ("progress") and a raw ISO timestamp (`project_page.dart:304-307`) while the workspace card two screens away renders "进展 · 8 小时前" from the same data — the l10n keys exist. The PRD desk shows three big section cards with no body, no placeholder, and borderless fields (`prd_desk.dart:96-107`), so the first-run user has no idea the coach's questions are meant to be answered there. The versions readiness list mixes languages on one line: localized section name + raw server English gloss (`versions_stack.dart:184`). Smaller wobbles: clicking an idea card's title or body does nothing (only the tiny PRD chip works); the invite banner's hint ends in a dangling colon; "大段引语" renders as a permanent subtitle under the coach title with nothing beneath it; the cryptic manifesto line "没有标签，也没有文件夹。" floats centered below the only idea card.

**What I would do first.** Fix the dock layout: bound `bottomNavigationBar` to the already-defined 88px height and bottom-align the pill. That single change clears the content overlap on every screen, restores the create-project FAB, and makes the existing per-page bottom padding actually meaningful. Immediately after, wire the two silent dock dead clicks and the idea-card tap, re-run the sim walk in `scripts/sim`, and only then take the copy/IA pass (project heading, dashboard labels, destructive-row styling). The bones of a trustworthy product are visible on the landing page and ideas wall; the chrome between them is currently spending that trust faster than the screens earn it back.
