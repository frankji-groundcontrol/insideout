## Design-Fidelity Review — Cobalt-Neo Migration Gap Analysis

I compared the shipped Flutter client against the Cobalt-Neo target (0px radius, 2px container borders, hard 4px 4px 0 0 offset shadows, press-the-block interactions at 100ms, dark-first neutral gray ramp, cobalt-#3B5BFF palette retained). Evidence came from a full read of `client/lib/theme/cobalt.dart`, `cobalt_theme.dart`, `field_card.dart`, `cobalt_chip.dart`, `ink_motion.dart`, `chrome/product_dock.dart`, `features/auth/auth_door.dart`, `session/appearance.dart`, and `features/prd/coach_panel.dart`; `DESIGN.md`, `docs/design-system/cobalt/README.md`, and `docs/design-system/CHANGELOG.md`; the reference neo-brutalist brief; the pre-built code map; nine screenshots across both themes (01, 02, 04, 05, 08, 09, 14, 16 plus the capture index); and computed WCAG contrast ratios for every relevant token pair. A repo-wide grep confirmed there is no existing neo/brutalist mention anywhere — the migration spec is genuinely greenfield.

**What is already right.** The palette half of the contract is in excellent shape. `cobalt.dart:62-66` defines the hue50–hue950 ramp once, both themes mirror every semantic key (`cobalt.dart:102-154`), and the code map's token-discipline pass found almost no color bypasses — five hardcoded lines in features, zero `withOpacity`/`fromRGBO`. Cobalt-500 on white computes to 5.09:1, so primary actions pass AA today. Dark and light genuinely parity: shots 05/09 and 04/15 are faithful twins. The ideas-wall display type implements the lock's `clamp(64px,10vw,320px)` spec exactly (`ideas_page.dart:181-192`), and the bottom dock gives every signed-in surface consistent loop chrome. The failure is not execution quality — it is that the executed design is the wrong design.

**Finding 1 — there is no shadow system (Critical).** The `Cobalt` class contains no shadow or elevation tokens of any kind, and the theme suppresses the Material defaults: `cardTheme` has `elevation: 0` (`cobalt_theme.dart:56`), the AppBar has `elevation: 0` (:49). The only two shadows in the entire app are soft, blurred Material elevations — the auth modal (`auth_door.dart:79-80`, elevation 6, black at 35% alpha) and the dock (`product_dock.dart:31`, elevation 8). The neo-brutalist signature is an unblurred `4px 4px 0 0` cast on every container, and there is no substrate to hang it on. This matters beyond aesthetics: with 0px radius and 2px borders but no cast shadow, boxes go flat. I computed the current dark-mode surface separation — raised-on-base is 1.09:1, sunken-on-base 1.42:1, stroke-on-raised 1.45:1 — so in dark mode cards already barely separate from the page, and the reference system solves that with shadows plus border weight, not contrast.

**Finding 2 — the radius decree is inverted (Critical).** `cobalt.dart:72-75` defines `radiusControl = 12.0`, `radiusCard = 20.0`, `radiusHero = 28.0`, `radiusPill = 999.0`. Buttons, FilledButtons, text inputs, chips, the FAB, and the dock are pills by theme wiring (`cobalt_theme.dart:28-33`, `87-111`); FieldCard is 20px everywhere (`field_card.dart:28`); the auth card is 28px; the capture bar is a literal `StadiumBorder` (`ideas_page.dart:200`); and features hardcode further radii — `circular(99)` twice, top-radius 10 on the versions stack, and 12/4/3/1px corners on the roadmap canvas. Every shot confirms it: 01, 02, 08, 14, and 16 are a sea of pills. Against a 0px-by-decree target this is the single widest-scoped change.

**Finding 3 — no press-the-block interaction exists (Critical).** The target's feel is hover: shadow 4→2px + translate(2,2); active: shadow gone + translate(4,4); 100ms. I grepped the whole client: the only `MouseRegion` is the roadmap canvas's remote-cursor tracker. Tappables get Material's default ink splash (`field_card.dart:35-39`) and one unrelated 180ms selection fade on the dock (`product_dock.dart:162`). The motion file (`ink_motion.dart`) is a mount-reveal system — 650ms expo ease — philosophically opposite to fast mechanical press motion, and there are no duration/curve/offset tokens to implement the target with.

**Findings 4–6 — borders, dark ramp, theme default (High).** Every container border is a default-width 1.0px `BorderSide` in cobalt-200 (`field_card.dart:29`), a 1.49:1 hairline in light mode; focused inputs and the dock's unfinished outline are already 1.5px, so widths drift. The dark ramp is blue-tinted — ground `#0B0D12`, raised `#141820`, sunken literally `hue950` (`#1E2A5A`) — not the neutral `#000/#111/#1A1A1A/#222 + #333 border` ladder, and shot 05 shows three near-identical navy blacks where elevation should be. And the app is light-first: `Appearance({..., this.dark = false})` (`appearance.dart:36`) with no `prefers-color-scheme` fallback — the inverse of the dark-first requirement.

**Findings 7–12 (Medium/Low).** Status semantics are cobalt washes — `statusSuccessBg: hue50`, `statusWarnBg: hue200`, `fgDanger: hue700` (`cobalt.dart:116-126`) — so done/warning/danger differ only by cobalt step, and the app's only true red is a hardcoded `#B3261E` in `admin_section.dart:167`. The coach panel is an off-ladder always-dark navy built on `Cobalt.hue950` with dark mode detected by `surfaceBase == Cobalt.darkGround` identity (`coach_panel.dart:111-112, 231`) — visible staying navy in light shot 15. Light-mode wells are brand-tinted (`surfaceSunken: hue50`). There is no 4px spacing scale, both body roles are 17.5px, and paddings are per-widget ad hoc. The dark shadow color is undefined (the dock hand-rolls 18% lightInk). And `DESIGN.md:27-45` still prescribes the rounded lock — it even disagrees with code (doc control radius 9999px vs `radiusControl` 12.0) — so the documented contract will fight the migration until rewritten alongside a CHANGELOG 2.0.0 major bump.

**What I would do first.** Nothing above can be coded until the values exist. Draft the Cobalt-Neo token table — dark and light gray ramps, border widths (2px container / 1px divider), cast and pressed shadows with an explicit dark-mode shadow color, press-motion tokens (100ms, offsets, curve), the semantic-hue policy, the type/spacing scale decision, and the dark-first default — as a dated reviewed plan, then land it as `Cobalt` 2.0.0 with the theme-level widgets (FieldCard, ShadeChip, AuthDoor, ProductDock, button/input themes) converted before any feature screen is touched.
