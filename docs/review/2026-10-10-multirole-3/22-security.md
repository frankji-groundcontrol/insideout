### The seams I probed and found sound

**Auth on every route.** The whole surface is one mux assembled in `server.go:92-124`; every registration except `/healthz`, the HMAC-authenticated webhook, and the declared `/api/v1/auth/` prefix is wrapped in `requireAuth` (middleware.go:158-173). The AST scan test is the enforcement, and its vacuity guard (`checked < 40` fails the test) means it cannot silently rot. `requireAdmin` chains requireAuth with `system_role='admin'`, and admin is reachable only through the `promote-admin` operator subcommand on the owner pool (cmd/insideout/main.go:86-94) — no self-promotion path exists.

**RLS discipline.** `withUserContext` (pool.go:147-161) sets `app.user_id` per transaction; I traced every bare `s.Pool` query in the store: the two documented pre-auth users paths (users.go:42-47), the auth-token/session/invitation tables (no RLS — single-app-role threat model, hashes only), the reaper's ai_runs update (NULL-context allowance written in its own migration, 20260721160000), telemetry/circuit functions, and the webhook's `SECURITY DEFINER _projects_by_repo` helper (20260821120000). The just-landed `20261010120000`/`130000` pair closes the ex-member author branches with table-qualified DEFINER helpers — correct in shape; it just needs to *reach the hosted DB* (SEC-01). The migrate pool is used for DDL only; no owner-pool path trusts where the app role would not.

**Webhook + outbound fetch.** Signature first, always, constant-time (`hmac.Equal`, github/webhook.go:25), 503 when unconfigured, one project's failure cannot block the others, and every write re-runs as the resolved project owner inside normal RLS. All outbound GitHub calls are pinned to `apiBaseURL = "https://api.github.com"` (github.go:49) — the only injection surface is SEC-06's query-string shaping, and the only unbounded read is SEC-02.

**The model as adversary.** The tool surface is six fixed tools with enum-checked arguments (agent/tools.go:23-88); stage gates are mechanical server-side (`checkStageGate` "does not trust the model's say-so", tools.go:242-297); the tool loop is bounded at 12 iterations (coach_loop.go:16); roadmap plans are drafted and applied only on a separate human confirm (roadmap_ai.go:63-147, 220-265); PRD-derived text is fenced so it cannot issue instructions (prompt_fence.go) — and every LLM call, coach turns and planner calls alike, passes the per-user rate limit, the circuit breaker, and the concurrency permits (agent/gate.go:16-101).

**Client and tokens.** Secure storage by default (client/lib/session/token_store.dart:62-88), refresh rotation with replay detection (`RotateSession` conflict → 401 + cookie clear, auth.go:222-230), reset revokes all sessions (auth_email_flows.go:182-187), httpOnly+Secure+Lax cookies with the refresh cookie scoped to `/api/v1/auth` (cookies.go:19-38), and MCP/CLI keep tokens out of conversation output with a 0600 config file (clientconfig Save; mcpserver/auth_tools.go).

**Secrets hygiene.** `.env.example` is a documented schema with `change_me` placeholders; `hosts/*/keys` tracks only YAML manifests (`.secrets/` gitignored, files created 0600 by scripts/keys.py:166-193); `backup-db.sh` dumps to gitignored `backups/` requiring the owner DSN; the dev postgres is explicitly bound `127.0.0.1` in compose because it ships default passwords (docker-compose.yml:24-27).
