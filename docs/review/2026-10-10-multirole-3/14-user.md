# Review 3 — User role: walking the happy path at 754c502

I read README.md, PRODUCT.md, docs/usage/local-development.md, the l10n catalogs, and the client/server code for every step of the advertised loop (install → invite signup → workspace → idea → PRD → coach turn → roadmap → Commit → export → audience view), plus one set of live read-only probes against the hosted deployment the CLI compiles in. This report is that walk, written from the seat of the person the product is for.

## The walk, in prose

**Install.** The README's first command is `curl -fsSL …/releases/latest/download/bootstrap.sh | bash`. I ran `git tag -l` on the checkout: zero tags, so `releases/latest` 404s today. The sentence above the block ("Once a `v*` release is tagged") discloses the condition, but a new user reads commands, not conditionals. The source path (`./scripts/install.sh`, Go 1.25+) works and is honestly documented — for developers. **USER-05.**

**Sign up by invite.** The flows themselves are the most honest code in the client: the register form asks the server whether the invite field should show (auth_form.dart:60-74), a 403 on register maps to invite-specific copy that admits "try again cannot fix it" (auth_form.dart:133-140), magic links have a dead-link state instead of a spinner-forever (magic_link_page.dart:66-78), and a MailOffNotice annotates the emailed options when the server says mail is off. The problem is one layer down: the hosted box every prebuilt binary targets (`DefaultBase`, default_base.go:8) answered my probe `curl https://insideout.yalotein.net/api/v1/auth/config` with `{"signupMode":"invitation_only"}` — no `mailEnabled` field, which the current auth.go:46 always ships. That is a pre-wave build, and on it the mail key is unset (lead 15), so the code-link, sign-in-code, and forgot-password paths accept the request, log the mail, tell the user "sent", and deliver nothing. The current client at least defaults a missing flag to mail-on (client_auth.dart:104 `?? true`), which is the wrong default for exactly the server shape that omits it. **USER-02.**

**Workspace and idea.** After register, the dashboard's empty state is well-written and offers Create/Join; the idea wall's capture keeps your text on failure and only clears on success (ideas_page.dart:82-92); "Convert to PRD" navigates straight to the PRD desk. One small strand: with zero workspaces, the dashboard's "Capture an idea" opens the workspace-create form and then leaves you on the dashboard (dashboard_page.dart:89-96). **USER-09.**

**Coach a turn.** The panel is genuinely good product: per-stage suggestion chips in both languages, a 75-second idle timeout so a frozen proxy can't hang the composer (sse.dart:132), undelivered text restored to the composer on failure (coach_panel.dart:141-143), and a server whose terminal-state guarantee persists whatever streamed when you disconnect, marking it `[interrupted]` (coach.go:153-177). Refresh mid-turn therefore lands you in history with your message and the partial reply — the right behavior, marred only by the hardcoded English marker (coach.go:168). **USER-08.** But the walk hits a wall: the coach's stage machinery proposes a stage and tells the model `stage %q is waiting for confirmation` (tools.go:239); the store even implements the confirmation SQL (agent_conversations.go:145-146); the route is registered (conversations.go:16) — and no surface calls it. I grepped client/lib/api, server/cmd, and server/internal/mcpserver: zero callers. Meanwhile the client treats the proposal as fact (prd_page.dart:277-291), so the header says "Drafting" until refresh reveals the server never left "Clarifying" — and since conversation completion is gated on the confirmed stage reaching finalize (coach.go:274), no conversation on any surface can ever finish. This is PRODUCT.md principle 6 ("Human authority stays explicit") implemented as a door with no handle. **USER-01.** And looming over all of it: the coach has never once run against a live provider (lead 13), while the offline template that stands in replies in Chinese with env-var instructions and is visually indistinguishable from real coaching (template.go:26, sse.go:53-54). **USER-03.**

**Roadmap, Commit, export.** These steps earn trust. "Draft the roadmap" auto-creates the project (roadmap_plan.go:183-186) and handles replace-conflict with a counted, dangerous confirm (prd_page.dart:171-191). The Commit modal carries audience, summary, decision note, and a live count of open items that will ride along unresolved — "forming a version now keeps gaps visible" is the PRODUCT.md promise, implemented (versions_commit_dialog.dart:123-131). Deadlines exist on nodes; progress and bands and canvas are three views of one fetch. Export offers markdown and print with audience projections. The gap is sharing: `/prd/:id/view` is an authed app route (router.dart:48); the only way a boss reads the Decision view is an exported .md or an account. PRODUCT.md's "scoped feedback invitation without joining the Workspace" (line 254-259) has no implementation. **USER-04.**

**zh locale, second visit.** I diffed the catalogs: 379 keys in en, 379 in zh, zero used keys missing, zero en-without-zh — including all four stage names and twelve audience-gap strings in both. First paint, however, is zh-CN for everyone regardless of browser language (l10n.dart:4; appearance.dart:63-70 reads only a saved choice). **USER-06.** Second visit hydrates the session with refresh-and-retry and a 15s bound (session.dart:46-60) — correct. One copy wart: the coach masthead strapline is the design-spec string itself — 'Large pull-quotes' / '大段引语' (coach_column.dart:292). **USER-07.**

## What already earns trust

- l10n parity is total and I verified it by diffing all five catalog files per language against every `t('…')` call site — 379/379 keys, no gaps, including the zh private-hint that explains the admin exception.
- The coach's failure story is the best in this codebase: server-side terminal-state defer with detached bounded persistence (coach.go:153-177), client idle timeout and composer restore (sse.dart:132, coach_panel.dart:141-143), and 401-on-stream handled eagerly so the router lands on the auth door (sse.dart:264-287).
- Every write I walked goes through `guardWrite` with localized errors and preserved input (guarded_action.dart:13-31; ideas_page.dart:82-92).
- The Commit flow implements the product's best idea — audience-scoped readiness with gaps deliberately carried (versions_page.dart:53-81, versions_commit_dialog.dart:123-131).

## The first three minutes, rewritten as they should be

0:00 — I open the deployment URL. The page opens in my browser's language (zh if I'm zh, en otherwise), one toggle away from the other. 0:10 — I click the primary CTA. The register form already knows this server is invitation-only and shows the invite field; if I have no code, the page says so in plain words and offers to tell me who to ask — not a bare 403 after submit. 0:30 — I'm in. The dashboard's one button says "Capture an idea"; pressing it with nothing set up creates the workspace *and* lands me on the idea wall in the same gesture, cursor already in the field, with a line telling me the idea is private until I convert it. 1:00 — I jot one sentence and press Convert. The PRD desk opens with the coach column up; if this server runs the offline template, a quiet badge on the masthead says "offline coach — canned replies", so the canned reply teaches me the loop instead of impersonating a mentor. 1:30 — I ask my first question. Real tokens stream. The coach proposes the next stage and the panel shows *proposed*, with two blocks: Confirm and Not yet — my decision, persisted, exactly as the door on the server was always built to be. 2:30 — I press "form a version now" from the coach column itself; the Commit modal names the audience, counts what rides along unresolved, and my name goes on version 01. 3:00 — I press Share on the Decision view and copy a read-only link I can paste to my boss without creating him an account. Every one of those beats exists in this repository in pieces — the missing minutes are one confirm control, one disclosure badge, one routed redirect, one shared link, and one deployed, mail-configured, live-coach rehearsal.
