# 24 · Reliability & Ops

**Lens:** graceful shutdown & goroutine lifecycle, outbound-call timeouts/retries, SSE connection lifecycle, DB pool & migrations, compose/Dockerfile restart & health behavior, deploy docs & freshness, logging hygiene (PII/secrets), offline-coach & mail fallbacks
**Score:** **6.5 / 10**
**Bottom line:** The Go runtime is engineered to a high reliability standard — every outbound HTTP client has explicit timeouts, the LLM path has a classified retry taxonomy, an idle watchdog, a circuit breaker, and a DB-backed reaper, and the coach's terminal-state guarantee survives client disconnects and panics. The packaging and operations layer is where the rot is: the compose file cannot be parsed without postgres-only secrets (the documented remote-DB path is dead), the server service forwards so few variables that email login silently never delivers on a self-host, the container runs as root with no healthcheck, the nginx-at-boot DNS fragility is a manual ritual with no tracked issue, and the two load limits the plan names were never wired to env. `go build`/`go vet`/`go test` all green, verified independently.

Reviewed against main@877ad03; High/Critical findings re-checked by an independent skeptic — verdicts in [01-findings-register.md](01-findings-register.md).

## Scope
Server lifecycle and HTTP plumbing (`cmd/insideout/main.go`, `internal/httpx`, `internal/api/{server,middleware,healthz,presence_routes,roadmap_ai,auth_email_flows}`), LLM/agent streaming (`internal/agent/{llm,anthropic,responses,taxonomy,coach,dispatch,sse}`), store pool + migrations, `internal/mail`, `internal/apiclient`, `internal/github` timeout grep, `internal/config`, client SSE transport and reconnect, `client/nginx.conf`, both Dockerfiles, `docker-compose.yml`, `.env.example`, `docs/usage/deployment.md`, `docs/HANDOFF.md`, `docs/issues/`, `docs/plans/README.md`. Ran `docker compose config`, `go build`/`go vet`/`go test ./...`.

## What is good
- **Every outbound HTTP client has an explicit timeout, verified by grep.** LLM streamers: dial 10s / TLS 10s / response-header 30s, no overall timeout deliberately (SSE runs minutes) plus a 90s idle watchdog (`server/internal/agent/anthropic.go:49-61`, `taxonomy.go:24,71-100`; same in `responses.go:33-43`). GitHub 15s (`server/internal/github/github.go:144`, `appauth.go:93,147`), Resend 10s (`server/internal/mail/mail.go:33`), CLI/MCP client 20s (`server/internal/apiclient/apiclient.go:28`). Repo-wide grep for naked `http.Get`/`http.DefaultClient` finds only a test fixture.
- **Classified failure taxonomy with bounded retries:** one retry for 429 (Retry-After capped at 20s) and 5xx with jitter (`taxonomy.go:36-65`); in-stream provider errors map to the same sentinels (`anthropic.go:334-349`); circuit results recorded per class (`coach.go:281-316`).
- **Coach terminal-state guarantee:** a deferred cleanup fails the run on every non-success path including panic, persists partial text on a detached 10s-bounded context, and separates client disconnects from upstream stalls (`coach.go:48-62,174-198`).
- **Presence SSE lifecycle is complete both sides:** 10s heartbeat ping doubling as session refresh, TTL prune, leave-on-disconnect (`server/internal/api/presence_routes.go:112-137`), client reconnect with capped backoff treating 401/403/404 as fatal (`client/lib/features/project/roadmap_page.dart:50-70`); nginx is SSE-safe (`proxy_buffering off`, `proxy_read_timeout 3600s`, `client/nginx.conf:24-26`).
- **Crash recovery without humans:** `runReaper` fails ai_runs orphaned by a dead process (`main.go:197-229`); migrations are filename-ordered, transactional, record in the same tx, none uses `CONCURRENTLY` (`server/internal/store/migrate.go:77-103`).

## Findings

**REL-01 · High · broken install on the documented self-host path** — `docker-compose.yml:17` + `docs/usage/deployment.md:24-25`. Quote: `INSIDEOUT_OWNER_PASSWORD: ${POSTGRES_OWNER_PASSWORD:?set POSTGRES_OWNER_PASSWORD in .env}` and "simply don't start it (`docker compose up -d server`)". I ran `docker compose config`: exit 15, "required variable POSTGRES_OWNER_PASSWORD is missing a value" — compose interpolates the whole file, so the documented escape hatch of running only `server` against a remote database fails at parse time; even `docker compose build` is unusable without postgres-only secrets. Failure scenario: operator with a remote Postgres follows deployment.md → every compose command errors → self-host is dead. Fix: change both `:?` guards to `:-` and enforce presence in `docker/postgres-init/` or an entrypoint check that runs only when the bundled postgres starts. diff_size: ~4 lines.

**REL-02 · High · bearer-equivalent secret written to application logs** — `server/internal/mail/mail.go:49` + `server/internal/api/auth_email_flows.go:285`. Quote: `s.log.Info("mail dev mode — not sent", "to", to, "subject", subject, "text", text)` where text contains `link := s.cfg.PublicURL + path + "?token=" + token` — a one-time sign-in token valid 15 minutes, printed at Info to stdout. Failure scenario: any environment without `INSIDEOUT_MAIL_API_KEY` (the compose default, REL-03) → every magic-link/reset request logs a live login URL plus the recipient's email. Fix: log `to`/`subject` only, drop `text` (`.env.example:101` even advertises "links included" — change that line too). diff_size: ~2 lines.

**REL-03 · Medium · compose cannot configure mail/GitHub/CORS, so email login silently never delivers** — `docker-compose.yml:38-52`. The server service forwards only ADDR, `DATABASE_URL`, `DATABASE_OWNER_URL`, `INSIDEOUT_JWT_SECRET`, and four `INSIDEOUT_LLM_*` vars; the catalog at `.env.example:99-133` (`INSIDEOUT_MAIL_API_KEY`, `INSIDEOUT_MAIL_FROM`, `INSIDEOUT_PUBLIC_URL`, `INSIDEOUT_GH_*`, `INSIDEOUT_CORS_ORIGINS`, `INSIDEOUT_COOKIE_SECURE`, both TTLs) never reaches the container. Failure scenario: self-hosted user requests a magic link → uniform 200 → `mail.Send` dev-mode logs and returns nil (`mail.go:48-50`) → no email ever exists and nothing errors; `INSIDEOUT_PUBLIC_URL` would still default to localhost even if a key got in. GitHub webhooks/App auth are likewise unconfigurable. Fix: forward the full catalog in the compose environment block. diff_size: ~12 lines.

**REL-04 · Medium · build/expand LLM endpoints bypass the coach's rate-limit/circuit/permit gate** — `server/internal/api/roadmap_ai.go:73` vs `server/internal/agent/coach.go:92-132`. Quote: `tree, err := s.planner.PlanMVP(r.Context(), prd.Title, prd.Sections)` — `handleBuildFromPrd`/`handleExpandNode` call the planner with no `CheckRateLimit`, no `CheckCircuit`, no dispatcher permit, while `HandleMessage` runs all three before any LLM work. Failure scenario: provider outage or abusive script → `/build` keeps hammering the provider (streamer retry still fires), the circuit never opens for this traffic, concurrent builds are uncapped. The dated issue `docs/issues/2026-07-25-build-from-prd-runs-llm-before-conflict-guard.md` tracks conflict-guard ordering only, not gating. Fix: extract the gate from `HandleMessage` into a shared helper used by both handlers. diff_size: ~25 lines.

**REL-05 · Medium · server container runs as root with no healthcheck anywhere** — `server/Dockerfile:8-11`, `docker-compose.yml:30-54`. Quote: `FROM gcr.io/distroless/static-debian12` … `ENTRYPOINT ["/insideout"]` — no `USER`, no `HEALTHCHECK`; the compose `server` service has no healthcheck (only `postgres`, lines 24-28) even though `/healthz` pings the DB (`server/internal/api/healthz.go:9-15`) and deployment.md:160 documents it as the Railway healthcheck. Failure scenario: a server that passes `depends_on` then fails migrations or loses DB connectivity stays "up" with no restart signal, running as root. Fix: `USER nonroot:nonroot` plus a compose `healthcheck` on `/healthz` (a Dockerfile HEALTHCHECK needs a binary distroless lacks). diff_size: ~8 lines.

**REL-06 · Medium · the two dispatch limits named in the plan are hardcoded** — `server/internal/agent/coach.go:42-46`. Quote: `defaultMaxConcurrent = 4` / `defaultQueueWait = 15 * time.Second` under "AI_MAX_CONCURRENT / AI_QUEUE_WAIT defaults — see plan §9 open question 2" — grep shows `AI_MAX_CONCURRENT` appears only in that comment; nothing reads it. Failure scenario: the Cobalt launch raises concurrent coach traffic; the only knob between a busy hour and `CIRCUIT_OPEN` 503s is a rebuild. Fix: read both from env in `New()` with current values as defaults. diff_size: ~8 lines.

**REL-07 · Medium · the nginx-at-boot DNS 504 fragility is a hand ritual, not a tracked issue** — `docs/HANDOFF.md:56-60`, `client/nginx.conf:17`. Quote: "its nginx resolves the server's internal address only at startup, so `/api` via the domain 504s until then" and `proxy_pass http://server.railway.internal:8080/api/;` (literal hostname, no `resolver` + variable form). `grep -rn "504\|nginx\|railway.internal" docs/issues/` returns nothing — every server redeploy ships a guaranteed public API outage until a human restarts `app`. Failure scenario: routine `railway up --service server` → domain 504s for `/api` until someone redeploys app. Fix: open a dated issue per AGENTS.md ("bugs get dated issues") with the bounded fix prompt: nginx `resolver` + variable `proxy_pass` so DNS re-resolves. diff_size: unknown.

**REL-08 · Medium · SSE write side is unbounded and ignores write errors** — `server/internal/agent/sse.go:34-41`. Quote: `fmt.Fprintf(s.w, "event: %s\ndata: %s\n\n", name, b)` / `s.flusher.Flush()` — return values discarded; no `WriteTimeout` on the server (`main.go:144-154`, deliberate) and nothing else bounds a blocked client write. Failure scenario: client freezes mid-stream without closing TCP (backgrounded mobile tab, half-open LB) → send buffer fills → `Flush` blocks forever; the idle watchdog cancels the provider request but cannot unblock the client write, so the goroutine — holding the conversation lock and a provider permit — leaks until restart; the reaper marks the run stale but cannot release the lock. Fix: make `sse.event` return its write error and abort the turn, or set per-write deadlines. diff_size: ~10 lines.

**REL-09 · Low · graceful shutdown burns the full 30s with connected SSE clients** — `server/cmd/insideout/main.go:166-173`, `server/internal/api/presence_routes.go:114-118`. `http.Server.Shutdown` does not cancel handler contexts; the presence loop exits only on `r.Context().Done()`, so every deploy/restart with live canvas tabs waits the whole `30*time.Second` window, logs a shutdown error, then exits. Failure scenario: rolling restart with 5 connected users → 30s deliberate stall each time. Fix: cancel a server-lifetime context in `RegisterOnShutdown` and select on it in stream handlers. diff_size: ~6 lines.

**REL-10 · Low · personal email logged at Info** — `server/cmd/insideout/main.go:89`. Quote: `log.Info("promote-admin: done", "email", email)` — the promoted admin's email lands in platform logs; `seed.go:67-68` also logs the demo password, though that one is a hardcoded well-known dev constant. Fix: drop the email attribute. diff_size: 1 line.

**REL-11 · Low · pgxpool runs entirely on library defaults** — `server/internal/store/pool.go:46-70`. `openPool` parses the DSN (only flipping protocol for `pgbouncer=true`) and never sets `MaxConns`, `MaxConnLifetime`, or `HealthCheckPeriod`. Defaults are sane for one small instance, but capacity against the shared-instance pooler is accidental, not decided. Fix: set explicit pool limits in `openPool`, documented in the deployment guide. diff_size: ~4 lines.

**REL-12 · Low · hosted deploy freshness unverifiable; records say it is behind** — `docs/plans/README.md:13-14`, `docs/HANDOFF.md:10-11`. Both rows still say "Merge PR #3, then `railway up --service app`"; `git log` shows PR #3 merged at 877ad03 (2026-09-18) with no changelog or deploy record after. Failure scenario: the hosted instance silently serves pre-Cobalt code while docs claim otherwise. direction: verify and record; first_check: `railway deployment list --service server`, compare the deployed commit to 877ad03, then close the loop in HANDOFF and a dated changelog.

## Recommendations
1. Make `docker compose config` succeed without postgres-only secrets (REL-01) and forward the full env catalog — mail, GitHub, CORS, cookie, TTLs, `INSIDEOUT_PUBLIC_URL` — to the server service (REL-03); until then the self-host story is broken in two places.
2. Strip token-bearing `text` from the dev-mode mail log before any self-host or misconfigured env ships (REL-02).
3. Before the pending `railway up` refresh, wire the two dispatch limits to env — `INSIDEOUT_AI_MAX_CONCURRENT`, `INSIDEOUT_AI_QUEUE_WAIT` — and set explicit pgxpool `MaxConns`; these are the two limits to set before the next run (REL-06, REL-11).
4. Add `USER nonroot` to the Dockerfile and a compose `/healthz` healthcheck on the server service (REL-05).
5. File a dated issue for the nginx DNS-at-boot 504 ritual with the resolver/variable-proxy_pass fix prompt (REL-07), and refresh HANDOFF/plans rows whose next action ("merge PR #3") is already done (REL-12).
6. Extract the coach's rate-limit + circuit + permit gate into a shared helper used by build/expand (REL-04).
7. Make SSE writes error-checked so a dead client aborts the turn instead of wedging the goroutine, and cancel stream handlers on shutdown so restarts don't burn 30s (REL-08, REL-09).

## What this role would do first
Set the two limits before the next run: wire `AI_MAX_CONCURRENT` and `AI_QUEUE_WAIT` to env (hardcoded at 4 permits / 15s queue in `coach.go:43-46`, named in the plan but never plumbed) and choose their values deliberately for Cobalt-launch traffic — they are the only thing between a busy coaching hour and a wall of `CIRCUIT_OPEN` 503s, and today changing them means a rebuild mid-deploy. In the same pass fix REL-02, because the compose fixes (REL-01/REL-03) will push more deployments into exactly the dev-mode-mail configuration that leaks live sign-in URLs into logs.
