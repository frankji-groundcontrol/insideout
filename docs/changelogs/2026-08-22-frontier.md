## Proposal→structure application

- Migration `20260822130000`: `proposal_items` (add_node actions with
  optional parent hint, immutable, member RLS).
- `POST /agent/propose` accepts `items[]` (≤10); `POST
  /agent/proposals/{uid}/decision` accepts `apply` — on acceptance the
  items become real roadmap nodes created as the deciding human
  (parent hint matches a node title).
- CLI `propose --item Title[@Parent]` and `proposal-decide --apply`;
  MCP mirrors (`items` array, `apply` boolean).
- Verified live: propose with one item → accept+apply →
  `appliedNodes: 1`, roadmap 17→18 nodes with the proposed title. One
  real bug fixed on the way: the apply path's project lookup ran on
  the bare pool (no RLS context) and silently applied nothing — moved
  under the decider's user context.

## Canvas cursors

- `presence.Registry.Cursor` / `SubscribeCursors`: ephemeral
  high-frequency broadcast, nothing stored, per-project isolation
  (unit-tested).
- `POST /projects/{id}/cursor` (member auth, per-tab client id);
  the presence SSE stream now also emits `event: cursor`.
- Web canvas: `MouseRegion` reports content-space moves (throttled to
  5/s), other sessions' cursors render as labeled pointers in the
  scroll overlay, dropped when their session leaves presence.
- Verified live: a watcher's stream received the mover's cursor event
  with exact coordinates (`x:123.5, y:45`).
