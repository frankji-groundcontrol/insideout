# 2026-07-28 — env.sh: interactive .env setup + validation; dev.sh preflights it

The root `scripts/dev.sh` ([added earlier today](2026-07-28-devsh-root.md))
exported `.env` and failed loudly when the file was missing — but nothing
helped you *set* the keys, and nothing validated them before the Go server's
own fail-fast fired. Now [`scripts/env.sh`](../../scripts/env.sh) does both,
and `dev.sh` preflights it. Roles are strictly split: **env.sh sets `.env`
up and validates it; dev.sh runs things** (running `env.sh check` first and
refusing to launch on any FAIL). env.sh never calls dev.sh, so there is no
cycle.

## What changed

- **Added [`scripts/env.sh`](../../scripts/env.sh)** (executable, bash 3.2
  compatible — no associative arrays / `mapfile` / `${var,,}`):
  - `init` — interactive, tty-only setup (refuses piped stdin so cron/pipes
    can't clobber the file). Walks `DATABASE_URL` (remote vs bundled-postgres
    setups, offers `docker compose up -d postgres`), `INSIDEOUT_JWT_SECRET`
    (generate via `openssl rand -hex 32` / type / keep, rejects under 32
    chars), the AI provider choice (empty token = offline template-reply
    coach), `GITHUB_TOKEN`, the plain-http `INSIDEOUT_COOKIE_SECURE=0`
    toggle, and — for the bundled postgres — the `POSTGRES_APP_PASSWORD` ↔
    URL-password match, with a `[r]ewrite` option that splices the new
    password into `DATABASE_URL` literally (awk + `ENVIRON`, immune to
    sed-hostile `&` / `\` / `#` in passwords). Write-back replaces the first
    `^#? *KEY=` line (uncommenting it) or appends, then `chmod 600`s the
    result. Never prints values: secrets show as `set (N chars)`, the DSN
    userinfo (user + password) as `***@host`, and secret prompts use
    `read -s`.
  - `check [--db]` — non-interactive validation and `dev.sh`'s preflight
    gate: required `DATABASE_URL` (warns on `change_me` / `your-remote-host`
    placeholders), required `INSIDEOUT_JWT_SECRET` ≥ 32 (prints the count,
    never the value), approximate Go-duration check on the two TTLs
    (compound `2h45m` and fractional `1.5h` accepted), exact-value checks on
    `INSIDEOUT_COOKIE_SECURE` / `INSIDEOUT_DEV_CORS`, offline-mode info for
    an empty `ANTHROPIC_AUTH_TOKEN`, the bundled-pg password match, and an
    optional `pg_isready` probe (stripping the pgx-only `?pgbouncer=true`
    query parameter libpq rejects). Exits 1 with a `hint: run ./scripts/env.sh
    init` line on any FAIL, 0 otherwise. `INSIDEOUT_ENV_FILE` overrides the
    file under test (how the suite below runs without touching the real
    `.env`).
- **`scripts/dev.sh` preflights it.** Before exporting `.env` and execing,
  dev.sh now runs `env.sh check` and aborts with the check's own output when
  a required key is missing or invalid — the failure names exactly what to
  fix, one step earlier than the Go server's `config.Load` fail-fast would
  have. (`config.Load` still fails fast on its own; the preflight is better
  UX, not a new guarantee.)
- **A 2026-07-29 follow-up (still before commit): `check` shows what you get
  by default.** It now prints which file it validated, reports the *defaults
  in effect* for every unset optional on stdout — each tagged with the
  consumer it reaches (Go server / Nuxt), emitted as `info`, never blocking —
  and makes an empty `GITHUB_TOKEN` visible (`info: … unauthenticated rate
  limit`). Because there is exactly one `.env` (the root one — the Go server
  reads the process env, Nuxt reads `NUXT_*` via the `dev.sh -C app` export
  and does not read the file itself), "where does this propagate" is answered
  per key as a consumer tag rather than a second file. The default strings
  are copied verbatim from `config.go` / `nuxt.config.ts` (`:8080`, `15m`,
  `720h`, `claude-sonnet-4-20250514`, `http://127.0.0.1:8080/api/v1`);
  `ANTHROPIC_BASE_URL` has none in config and is labelled "Go server
  fallback" — the constant in `server/internal/agent/anthropic.go` that fills
  an empty base URL (the client is hand-rolled `net/http`, no SDK).
  Compose-only vars (`POSTGRES_*`, `SERVER_PORT`, `APP_PORT`) are deliberately
  absent — they don't apply to dev-server runs. This pushed the script to
  365 lines, recorded as
  [a modularity issue](../issues/2026-07-29-envsh-line-budget.md).
- **New hands-on guide [`docs/SETENV.md`](../SETENV.md)** — recorded in its
  own [changelog entry](2026-07-28-setenv-guide.md).

## Verification

- `bash -n` clean on both scripts. Live sandboxed battery via
  `INSIDEOUT_ENV_FILE` temp files (the real `.env` is never read or
  printed): empty file → `FAIL: DATABASE_URL` + `FAIL: INSIDEOUT_JWT_SECRET`
  + hint line, exit 1; valid file → exit 0 with the DSN shown as
  `***@host` and the JWT as `set (64 chars)`; a password containing `@`
  (`postgres://u:AB@CD@host/db`) fully masked (`***@host/db`) with no
  fragment leaked; piped / `/dev/null` `init` → tty refusal, exit 1; no-args
  → usage, exit 2; `-h` → usage, exit 0; `check --bogus` → exit 2; compound
  / fractional TTLs no longer false-warn while `xyz` still does; placeholder
  values warn but exit 0; bundled-pg without `POSTGRES_APP_PASSWORD` → FAIL,
  exit 1; URL/password mismatch → warn.
- dev.sh both directions: the empty-file preflight aborts with the FAIL
  output and never execs the command; the success path with the real `.env`
  runs `go version` with masked check output only.
- Two earlier adversarial workflow passes (author → robustness + security
  verification → fixer) found and fixed before merge: a first-`@` anchoring
  bug that leaked the tail of a password containing `@`, a write-back path
  that left `.env` 0644, a sed escaper whose missed `#` delimiter aborted the
  whole init (losing all typed input), and an append-glue corruption on files
  lacking a trailing newline. All retested green on macOS bash 3.2.57 / BSD
  sed, including a pty-driven end-to-end `init` with a hostile password.
- A same-day follow-up (before commit) fixed two issues a live `--db` run
  against a Supabase pooler URL surfaced: the probe handed libpq the
  pgx-only `?pgbouncer=true` query parameter, which libpq rejects — a false
  `database not reachable` FAIL on a healthy database (the probe now strips
  that parameter in any position and keeps every other one); and the DSN
  display now masks the whole userinfo, not just the password, because
  pooler usernames embed project identifiers. Retested green: all four strip
  orderings, `@`-in-password masking via temp file, and the live probe →
  `database accepts connections`, exit 0.
- A 2026-07-29 follow-up (still before commit) re-ran the full battery plus
  the new cases: empty file → both FAILs plus all eight default lines, exit
  1; fully-set file → zero default lines, exit 0; a file setting only
  `INSIDEOUT_ACCESS_TTL` → that key's default line suppressed, the other
  seven printed; a missing file → one FAIL naming the exact path, exit 1;
  distinctive `DATABASE_URL` password + `GITHUB_TOKEN` values in the temp
  file → grep of the whole output proves neither appears. A default line also
  disappears when the variable is set in the *environment* (verified with
  `env -u ANTHROPIC_BASE_URL`), which is correct: `dev.sh` exports `.env`
  onto the live environment, so an inherited value genuinely reaches the
  server and no default is in effect. A three-lens adversarial pass (bash-3.2
  `set -e` semantics, defaults ground-truthed against `config.go` /
  `nuxt.config.ts` / `anthropic.go` / `github.go`, docs + records sync) then
  caught the `ANTHROPIC_BASE_URL` attribution (it is an in-repo constant, not
  a provider default), an over-narrow "on success" framing of the report in
  `environment.md` (it prints on the FAIL path too), and two non-existent
  helper names in the line-budget issue's target structure — all fixed above.

## Operator notes

- `.env` format is unchanged. New workflow: `./scripts/env.sh init` to set
  up, `./scripts/env.sh check` to validate. Personal scripts that exported
  `.env` by hand can keep working; nothing about the file changed.
- `check` exits 1 on FAIL, so CI can gate on it: `./scripts/env.sh check`
  (add `--db` to also probe connectivity when `pg_isready` is installed).
