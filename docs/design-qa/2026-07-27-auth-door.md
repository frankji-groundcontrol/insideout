# 2026-07-27 — Auth door: login/register as a prompted floating modal

One QA thread on the public auth pages' appearance. Both comments drove a
single implementation: `/login` and `/register` became one shared prompted
floating modal. Implementation detail lives in the
[changelog](../changelogs/2026-07-27-auth-door-modal.md); this file keeps the
verbatim feedback and its resolution.

## Entries

### "the login page is ugly, is it possible for you to refine it? for example, a motion to prompt a modal, and the seal logo is not applied"

**Resolution.** The first comment had already been partly answered by the
earlier same-day [login refinement](../changelogs/2026-07-27-login-page-refinement.md)
(real 印 seal + a card that surfaces like a modal). This thread is what
completed it: the surfacing motion becomes a *real* dialog, not a card
pretending to be one (see the next entry).

**Files touched:** [app/src/pages/login.vue](../../app/src/pages/login.vue),
[app/src/components/auth/AuthDoor.vue](../../app/src/components/auth/AuthDoor.vue).

### "can you make it a prompted floating modal with motion?"

**Resolution.** Yes — `/login` and `/register` are now thin pages that render
a single shared shell, `AuthDoor`: a paper panel floating over a dimmed scrim
with real dialog semantics — `role="dialog"` + `aria-modal`, a focus trap,
Escape and backdrop-click close (both navigate to `/`), scroll lock, and focus
restore. Those semantics were extracted from the existing `BaseModal` into a
shared composable and reused by `BaseModal` unchanged, so the app has one
dialog behavior, not two. Motion is the reduced-motion-gated seal stamp plus
the panel surfacing (opacity/y/scale) — the "prompt" the user asked for.
`register` also dropped its fake bordered-glyph placeholder for the real 印
seal, matching `login`.

**Visual follow-up (caught in verification).** The first cut's backdrop was a
flat opaque `bg-surface-overlay` (token `0 0 0`, no alpha) — a black wall that
erased the celadon ground in light mode, i.e. the same off-world "near-black
background" look the user was reacting against, just relocated behind the
panel. Fixed: the modal now paints its own world-ground (`bg-surface-base`) and
dims only the periphery with an ambient ink vignette, so the door floats within
the Ink & Seal world in both themes. The same verification also moved
`aria-modal` onto the wrapper (it had pruned the form from the a11y tree) and
made the backdrop `pointer-events-none` (the scrim had been swallowing the
backdrop-click close). See the
[changelog corrections](../changelogs/2026-07-27-auth-door-modal.md#corrections-after-adversarial--visual-verification).
